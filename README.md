# testloop-benchmark

The benchmark the thesis is evaluated on (proposal بند ۵-د; roadmap milestone M2).

**Status (2026-10-17): frozen as `benchmark-v1`.** 22 modules from 20
projects, 4 candidates rejected. The modules, their pinned commits and their
pinned mutant sets at tag `benchmark-v1` are never edited; every result in the
thesis names this tag. The BugsInPy and post-cutoff tiers are added later as
separate targets and do not change these 22.

| Category | Modules |
|---|---|
| Pure logic (7) | slugify, inflection, jsonpointer, toolz `itertoolz`, boltons `strutils`, humanize `number`, parse |
| Class-based / stateful (7) | semver `Version`, boltons `cacheutils`, cachetools, bidict `_base`, isodate `duration`, schedule, dateutil `relativedelta` |
| Parsing and I/O (4) | xmltodict, tomli `_parser`, python-dotenv `main`, python-dotenv `parser` |
| Third-party dependencies (4) | requests `utils`, marshmallow `validate`, jinja2 `filters`, click `types` |

Measured numbers for every candidate, including each module's own tests
(the "human" reference row): [screening/SUMMARY.md](screening/SUMMARY.md).
Mutation-engine validation against mutmut: [screening/MUTMUT-CROSSCHECK.md](screening/MUTMUT-CROSSCHECK.md).

## Files

- `manifest.toml`: every source repository with its pinned commit and test
  dependencies, and each module's category, import path, human tests and
  selection status.
- `targets/<id>.toml`: the target file `testloop` reads (generated by `tools/fetch.py`).
- `targets/<id>-mutants.json`: the module's pinned mutant set (Mutation Budget:
  at most 200 mutants sampled once with seed 0). A set refuses to load if the
  module's source differs from the pinned commit.
- `screening/`: per-module screening results and the summary table.

## Recreate it

```bash
python3 tools/fetch.py          # clones into ../_checkouts/, one venv per project
pip install -e ../testloop      # into the interpreter that runs the screen
python tools/screen.py --jobs 8 # re-measures the human tests, writes screening/
```

Selection criteria: mature PyPI project with its own tests for the module,
pure Python, mutation-feasible size, at least ~80 mutants (so per-module
statistics are meaningful), at most two modules per project, and a spread over
the four categories.

Still to add in M2: the BugsInPy subset (RQ4) and 3–5 modules from
repositories created after the models' training cutoff (contamination tier).
All 22 modules above are well-known projects that are almost certainly in the
models' training data.
